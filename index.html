mini-infer Pure PyTorch · Qwen2.5

Minimal continuous-batching inference engine built from scratch in pure PyTorch. Implements a Paged KV-cache memory manager with 16-token physical blocks and virtual block tables (eliminating >60% VRAM fragmentation), an iteration-level dynamic scheduler, and radix prefix block hashing. Features dual-model speculative decoding (0.5B draft + 1.5B target parallel verifier with Leviathan rejection sampling) with zero distribution drift.

3.81 GB VRAM for dual models · 43.6%–77.8% draft acceptance · SDPA kernels

EdgeSLM SmolLM2-360M · LoRA · ONNX

Document sensitivity classifier for local CPU inference. Combines a LoRA fine-tune of SmolLM2-360M with a regex security policy layer so confidential files never leave the machine. Evaluated on a held-out re-labelled dataset with 95% confidence intervals; the report documents unexpected findings, including why a TF-IDF baseline originally beat the fine-tune (91.7% vs 58.3%) and how INT8 quantization traded accuracy for speed.

Focus & Principles

My current work centers on the systems engineering of inference:

  • Memory layout: Paged KV-cache, block allocation, virtual-to-physical address translation, and zero-recompute prefix caching.
  • Execution efficiency: Iteration-level continuous batching, prefill/decode scheduling, and speculation algorithms (Leviathan rejection sampling).
  • Serving rigor: Statistical latency percentiles, queue dynamics, and real hardware telemetry (tokens/sec, tokens/Joule, VRAM peaks).
  • Reproducibility: Apache 2.0 open-source code, self-contained implementations without unneeded abstractions, and cross-platform CI.
