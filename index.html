streamspec v1.2.0 · AGPL-3.0

Runs 70B models and DeepSeek-R1 on consumer GPUs (8–16 GB VRAM) by streaming layers from disk or host RAM into GPU memory while previous layers are computing. Prefetches the next layer asynchronously over PCIe so the GPU doesn't stall waiting on I/O.

10x–15x faster I/O than naive offloading · >90% PCIe bus overlap
GitHub ↗ PyPI ↗ Hugging Face Space ↗ Colab Notebook ↗
▸ Architecture breakdown & silicon proof
The Bottleneck
70B parameter models require ~140 GB FP16 VRAM. Running on an 8GB or 16GB consumer GPU forces CPU/NVMe layer swapping, where single-token sequential passes stall the CUDA cores while waiting on PCIe bus transfers.
The Mechanism
Double-buffered pinned memory ring buffer that prefetches layer L+1 over DMA while layer L computes on GPU, hiding 90%+ of PCIe latency behind batched GEMM sweeps. Dynamic EMA modulates speculative draft candidate length K based on live acceptance rates.
Silicon Verification
Measured 10x–15x I/O throughput gains over baseline unbatched paging on an NVIDIA RTX 3050 (6GB). 10/10 automated test suites passing in CI.
mini-infer v0.4.0 · PyPI

A small continuous-batching inference engine built in pure PyTorch. Implements paged KV-cache memory allocation and iteration-level scheduling from scratch to demonstrate how modern serving systems avoid fragmentation and batch requests dynamically.

26.4 tok/s at concurrency=4 on RTX 3050 · 3.1x batch speedup
GitHub ↗ PyPI ↗ Hugging Face Space ↗
▸ Architecture breakdown & silicon proof
The Bottleneck
Standard sequential generation preallocates max-context contiguous GPU memory for each request, causing severe internal fragmentation and frequent CUDA Out-Of-Memory errors under concurrent workloads.
The Mechanism
Virtual memory block manager mapping non-contiguous GPU physical slots to logical token positions. Iteration-level continuous scheduling injects new prompt prefill passes alongside active decode tokens without waiting for previous requests to finish.
Silicon Verification
Benchmarked against Qwen2.5 and SmolLM2 on RTX 3050 Laptop GPU. Achieved 26.4 tok/s aggregate throughput at c=4 concurrency (3.1x speedup over sequential execution) with zero memory leaks.
servebench v1.2.0 · PyPI

Load testing tool for local LLM servers (vLLM, Ollama, SGLang). Streams HTTP SSE tokens with microsecond timestamps to measure time-to-first-token (TTFT) and inter-token latency (ITL) under concurrent user traffic.

152 unit tests passing · tracks tail latency percentiles
GitHub ↗ PyPI ↗
▸ Architecture breakdown & silicon proof
The Bottleneck
Generic HTTP load testers (e.g. ApacheBench, wrk) only record end-to-end response time, masking critical LLM streaming degradations like TTFT spikes, KV-cache queuing delays, and token jitter.
The Mechanism
High-throughput Server-Sent Events parser logging microsecond per-token arrival delta timestamps. Automates concurrency sweeps to map the latency knee where serving slots saturate.
Silicon Verification
Identified Ollama concurrency bottleneck at 4→8 slots under 44.8% Memory Bandwidth Utilization (MBU) on local hardware. 152/152 unit tests passing.
sched-sim v0.2.3 · PyPI

A CPU-based discrete-event simulator for benchmarking LLM scheduler policies (chunked prefill, prefix caching, prefill-decode disaggregation) without renting GPU clusters. Calibrated against real Ollama serving runs within ±12%.

Simulates 6 scheduler policies · exports Perfetto execution traces
GitHub ↗ PyPI ↗ Hugging Face Space ↗
▸ Architecture breakdown & silicon proof
The Bottleneck
Evaluating serving scheduling algorithms (Sarathi, Radix Attention, Disaggregation) typically requires provisioning multi-node GPU clusters, making rapid policy iteration slow and expensive.
The Mechanism
Analytical roofline model driven by memory bus bandwidth and FLOP limits. Simulates chained Radix hash trees and chunked iterations on CPU in seconds, exporting JSON trace dumps viewable on ui.perfetto.dev.
Silicon Verification
Simulated time-per-output-token (TPOT) matched real out-of-sample physical Ollama hardware runs within ±12%. 42/42 tests passing.
quantbench v0.1.2 · PyPI

Quantization experiments and benchmarks in PyTorch. Includes INT4 bit-packing into uint8 tensors, BitNet 1.58b ternary packing, Ampere 2:4 structured sparsity masks, and GPTQ second-order Hessian calibration.

3.5x INT4 compression · 47 test cases covering accuracy & speed
GitHub ↗ PyPI ↗
▸ Architecture breakdown & silicon proof
The Bottleneck
Naively applying sub-byte quantization (INT4/ternary) creates accuracy degradation and dequantization overhead unless weights are packed aligned to hardware registers and calibrated against Hessian matrices.
The Mechanism
Vectorized 2x INT4 nibble packing into uint8, 2:4 Ampere sparsity index condensation, and block-wise Cholesky Hessian damping updates with drop-in PyTorch QuantLinear layers.
Silicon Verification
Measured 3.5x memory reduction for INT4 and 7.5x for BitNet ternary packing on Llama/Qwen layers with zero-copy buffer hooks. 47/47 unit tests passing.
