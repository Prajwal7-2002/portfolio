From Scratch: Vectorized INT4 Bit-Packing, Ampere 2:4 Sparsity, and Second-Order Hessian Calibration in Pure PyTorch

Why naive quantization collapses under activation outliers, how two 4-bit signed nibbles pack into uint8 vectors, and how slashing DRAM traffic by 73.4% scales autoregressive decode throughput on consumer GPUs.

The Physics of LLM Decoding: Why Weights Are the Bottleneck

Most machine learning engineers treat quantization as an off-the-shelf black box: run AutoAWQ, download a GGUF checkpoint, and assume "4-bit quantization makes models fast because matrix multiplies are smaller."

In production LLM serving, that intuition is fundamentally incomplete. During autoregressive decoding (generating tokens one-by-one with batch size = 1), the computation is not compute-bound. It is 100% memory bandwidth bound.

The Operational Intensity Equation (Batch Size = 1):
For every linear layer with $N$ parameters, generating a single token requires multiplying activation vector $[1, 1, D_{\text{in}}]$ against weight matrix $[D_{\text{in}}, D_{\text{out}}]$. The arithmetic intensity $I$ is strictly: $$I = \frac{\text{FLOPs}}{\text{DRAM Byte Transfers}} = \frac{2 \cdot N \cdot 1}{N \cdot \text{bytes\_per\_param}} = \frac{2}{\text{bytes\_per\_param}} \text{ FLOPs/byte}$$

On consumer laptop hardware (such as our benchmark NVIDIA RTX 3050 6GB Laptop GPU with $192.0\text{ GB/s}$ DRAM bandwidth and an FP16 ridge point of $189.6\text{ FLOPs/byte}$):

  • FP16 Baseline ($2.0\text{ bytes/param}$): $I = 1.00\text{ FLOPs/byte}$ (Execution runs at less than $1\%$ of the GPU's Tensor Core FLOP capacity).
  • INT8 AbsMax ($1.0\text{ byte/param}$): $I = 2.00\text{ FLOPs/byte}$ ($49.9\%$ DRAM traffic reduction).
  • INT4 Blockwise ($0.53\text{ bytes/param}$ with scale overhead): $I = 3.76\text{ FLOPs/byte}$ ($73.4\%$ DRAM traffic reduction).
  • BitNet 1.58b Ternary ($0.25\text{ bytes/param}$): $I = 8.00\text{ FLOPs/byte}$ ($87.5\%$ DRAM traffic reduction).

Because $I \ll 189.6$, every single byte eliminated from the weight tensor directly and linearly translates into higher decode tokens per second. But how do you store and compute with sub-byte numbers in software without a C++/CUDA compiler?

The Catastrophe of Naive Quantization: Activation Outliers

If quantization were as simple as scaling all numbers into $[-127, 127]$, quantization would have been solved a decade ago. However, in modern transformer architectures (such as Qwen2.5, LLaMA-3, and Mistral), attention projection layers exhibit a severe phenomenon known as systematic activation outliers.

Approximately $0.1\%$ of the activation channels maintain magnitudes $100\times$ to $200\times$ larger than normal channels (e.g. $+174.0$ vs an average of $1.5$). If you quantize activations with naive symmetric AbsMax:

# The catastrophic failure of naive per-tensor AbsMax:
scale = activation.abs().max() / 127  # scale = 174.0 / 127 = 1.37
quantized = torch.clamp(torch.round(activation / scale), -128, 127)
# Result: Any normal channel with value 0.5 collapses to 0. Perplexity explodes to infinity!

SmoothQuant: Channel Migration & Exact Invariance

In quantbench, we implement SmoothQuant to migrate the outlier difficulty from activations into weights where dynamic ranges are much smoother:

$$s_j = \frac{\max(|X_j|)^\alpha}{\max(|W_j|)^{1-\alpha}}$$

The transformation divides activation channels by $s$ and pre-multiplies weight columns by $s$:

$$\hat{X} = X \cdot \text{diag}(s)^{-1}, \quad \hat{W} = \text{diag}(s) \cdot W$$

Because matrix multiplication is associative, the mathematical identity is exact: $Y = \hat{X} \hat{W} = (X s^{-1})(s W) = X W$. In our pure PyTorch implementation, maximum numerical drift across 8 batches of calibration data is strictly bounded below $2.86 \times 10^{-6}$, completely stabilizing INT8 GEMM.

Vectorized Sub-Byte Bit-Packing in Pure PyTorch

CPUs and GPUs address memory in bytes, not 4-bit nibbles or 2-bit ternary states. Storing a 4-bit integer inside an 8-bit container wastes $50\%$ of physical VRAM. To realize true hardware compression, weights must be bit-packed into vectorized torch.uint8 tensors.

1. INT4 Nibble Packing & Arithmetic Sign Extension

To pack two signed 4-bit integers $v_0, v_1 \in [-8, 7]$ into a single byte:

  1. Mask values to 4-bit unsigned representations: v & 0x0F.
  2. Bitwise-OR the lower nibble with the left-shifted upper nibble:
def pack_int4_vectorized(tensor: torch.Tensor) -> torch.Tensor:
    # tensor shape: (..., K), where K is even
    t_clamped = torch.clamp(tensor, -8, 7).to(torch.int8)
    u8 = t_clamped & 0x0F
    v0 = u8[..., 0::2]
    v1 = u8[..., 1::2]
    return (v0 | (v1 << 4)).to(torch.uint8)

During runtime dequantization in QuantLinear.forward(), recovering signed 4-bit values requires arithmetic sign extension. If you simply cast unsigned nibbles back to signed integers, negative values (e.g. $-1$, which is 0x0F) unpack into $+15$!

In quantbench, we solve this in pure vector operations by left-shifting the upper nibble by 4 bits, casting to signed int8, and arithmetic right-shifting by 4 bits so the CPU/GPU replicates the sign bit across the top 4 bits:

# Vectorized two's complement sign-extension dequantization:
v0_signed = ((packed << 4).to(torch.int8)) >> 4
v1_signed = packed.to(torch.int8) >> 4

2. BitNet 1.58b: SIMD Offset Binary vs Base-3

For ternary weights $\{-1, 0, 1\}$, information theory dictates that $\log_2(3) \approx 1.585\text{ bits}$ are needed per weight. A base-3 packing algorithm ($w_0 + 3w_1 + 9w_2 + 27w_3 + 81w_4 \le 242 < 256$) packs 5 weights into a single byte ($1.6\text{ bits/weight}$).

However, during forward pass GEMM on hardware, decoding base-3 requires sequential integer modulo and division instructions (div and mod), which stall GPU register pipelines. In quantbench, we built Biased SIMD 2-bit packing as the default runtime: mapping $\{-1, 0, 1\}$ to $\{0, 1, 2\}$ via $(v + 1)$, enabling four weights per byte using single-cycle parallel bit shifts without division bottlenecks.

NVIDIA Ampere 2:4 Structured Sparsity

Standard unstructured sparsity (zeroing out random weights below a threshold) creates irregular pointer lookups that slow down GPU execution. NVIDIA Ampere, Ada, and Hopper Tensor Cores introduced 2:4 Structured Sparsity: in every block of 4 weights, exactly 2 must be zero.

Dense Weight Row (4 weights):      [ 0.85,  0.00, -0.42,  0.00 ]
Retained Non-Zeros (2 weights):    [ 0.85, -0.42 ]  -> Condensed into (M, N/2)
Original Column Indices:           Index 0 (0b00) and Index 2 (0b10)
Packed 4-bit Metadata Nibble:      (0b00) | (0b10 << 2) = 0b1000 = 0x08

By packing two 4-element blocks (8 dense weights, 4 non-zeros) into a single uint8 metadata byte, storage overhead is strictly 2 bits per non-zero value. When running on Tensor Cores, the hardware fetches half the matrix and doubles peak TFLOPS.

Second-Order Error Compensation: GPTQ & Cholesky Damping

When quantizing weights to 4 bits, Round-to-Nearest (RTN) leads to accumulated reconstruction error. GPTQ solves this by treating quantization as an optimization problem over the layer's activation Hessian matrix $H = 2 X^T X$.

Using the classic Optimal Brain Surgeon formulation, whenever weight $w_q$ is quantized to $\hat{w}_q$, the remaining unquantized weights in the block receive a compensating update:

$$\Delta W_{:, j} = -\frac{w_q - \hat{w}_q}{[H^{-1}]_{qq}} \cdot [H^{-1}]_{:, q}$$

In practice, directly inverting $H$ is numerically unstable because activation Hessians in transformers are frequently rank-deficient. In quantbench, we apply diagonal Cholesky damping:

$$\hat{H} = H + \lambda \cdot \text{diag}(H), \quad \text{where } \lambda = 0.01 \cdot \text{mean}(\text{diag}(H))$$

In our calibration test on a $(512 \times 256)$ projection layer, GPTQ block-wise Hessian compensation dropped the Frobenius reconstruction error from $84.22$ down to $56.77$—a $1.48\times$ error reduction compared to Round-to-Nearest.

Install & Reproduce Locally

quantbench is open-source, Apache 2.0 licensed, and published as a pure-Python wheel on PyPI with zero compiled C++/CUDA requirements:

pip install quantbench-engine

Inspect sub-byte bit packing in your terminal:

# Run vectorized bit-packing inspector
quantbench pack-inspect --format int4
quantbench pack-inspect --format sparse24

# Run Quality-vs-Speed Pareto sweep
quantbench pareto --vocab-size 32000 --hidden-dim 2048

Explore the mathematical derivations, proofs, and source code on GitHub: github.com/Prajwal7-2002/quantbench.
